## Этап 1 — «Безопасность» (критично, блокирует прод)

### 1.1 🔴 B1 — Утечка 2FA-кода клиенту
**Файлы:** `src/services/authService.ts` (send2FACodeService, ~строки 219–259), `src/controllers/authController.ts` (send2FACode)
**Проблема:** `Math.random()`-код всегда возвращается как `{ debugCode }` в ответе API и пишется в консоль `console.log`, даже в проде.
**Действия:**
- `debugCode` возвращать/логировать только при `NODE_ENV !== 'production'`;
- в проде ответ `{ success: true, message }` без кода;
- заменить `console.log` на `logger.*` (dev-only уровень).

### 1.2 🔴 B2/B3 — Нет проверки доступа к чату (IDOR)
**Файлы:** `src/services/chatService.ts` (`sendMessage`, `markMessagesAsRead`)
**Проблема:** в отличие от `getProjectMessages`, нет проверки принадлежности проекта.
**Действия:**
- в `sendMessage` добавить `userRole` параметр и проверку: `if (userRole !== 'MANAGER' && project.partnerId !== senderId) throw AppError(403)`;
- то же в `markMessagesAsRead`;
- обновить контроллер `chatController.ts` (передача роли).

### 1.3 🔴 B4 — IDOR в 2FA: `userId` от клиента
**Файлы:** `src/controllers/authController.ts`, `src/services/authService.ts`, `src/routes/authRoutes.ts`
**Проблема:** `send2FACode`/`verify2FACode` доверяют `userId` из тела запроса.
**Действия (минимум для этапа 1):**
- короткоживущий pre-auth токен: при `login` с `requires2FA` генерировать signed-токен (с `userId`, exp ≤ 5 мин), класть в httpOnly cookie `preauth`;
- `send2FACode`/`verify2FACode` читают `userId` из cookie, не из тела;
- zod-схемы `twoFASendSchema`/`twoFAVerifySchema` — убрать `userId`.
**Согласовать с клиентом:** `src/store/useAuthStore.ts` (verify2FA/send2FACode) — после изменения контракта.

### 1.4 🟠 B5 — ADMIN не может редактировать проект
**Файлы:** `src/services/projectService.ts` (updateProject, ~строка 88)
**Действие:** `if (project.partnerId !== userId && userRole !== 'MANAGER' && userRole !== 'ADMIN')`.
**Тест:** добавить кейс в `tests/services/projectService.test.ts`.

### 1.5 🟠 B6 — Некриптостойкий 2FA-код
**Файлы:** `src/services/authService.ts` (~строки 219–220)
**Действия:**
- `const code = String(crypto.randomInt(100000, 1000000))`;
- `bcrypt.hash(code, 10)`.
**Тест:** добавить проверку формата кода (6 цифр) в `tests/services/authService.test.ts`.

### 1.6 🟠 B9 — JWT_SECRET без fail-fast проверки
**Файлы:** `src/server.ts` (после `config()`), `src/middleware/authMiddleware.ts`
**Действия:**
- в `src/server.ts` на старте: `if (!process.env.JWT_SECRET) { console.error(...); process.exit(1) }`;
- в `authMiddleware` — валидировать наличие секрета (или вынести конфиг в `src/config/env.ts`).
**Согласовать с клиентом:** клиентский `src/config/env.ts` уже централизует env — бэкенду добавить аналогичный `env.ts` (см. 4.3).

### 1.7 🟠 B13 — Socket refresh-ротация без детекта reuse
**Файлы:** `src/server.ts` (~строки 175–234)
**Проблема:** ручная ротация refresh-токена не проверяет `revokedAt`/`replacedByHash` (в отличие от `rotateRefreshToken` в `generateToken.ts`).
**Действие:** переиспользовать `rotateRefreshToken` (вынести из utils или дублировать проверку reuse с отзывом всех сессий).

## Этап 2 — «Rate limit и защита от злоупотреблений»

### 2.1 🟠 B7 — Rate limit на login/forgot-password
**Файлы:** `src/routes/authRoutes.ts`
**Действия:**
- `loginLimiter` = 10/мин на IP;
- `forgotPasswordLimiter` = 3/час на IP;
- навесить на соответствующие роуты перед контроллерами.

### 2.2 🟡 B14 — Ограничить `limit` в пагинации
**Файлы:** `src/services/projectService.ts` (getProjects, ~строка 42), `src/services/userService.ts` (getUsersList)
**Действие:** `const limit = Math.min(Math.max(1, parseInt(query.limit) || 10), 100)`.

### 2.3 🟡 B15 — Валидация `dynamicData`
**Файлы:** `src/utils/validationSchemas.ts` (createProjectSchema), `src/services/projectService.ts`

- убрать слепой `.passthrough()`, заменить на явный `.passthrough().refine(...)` или отдельную проверку.

### 2.4 🟡 B17 — Wildcard в поиске (ILIKE)
**Файлы:** `src/services/projectService.ts` (~строка 54), `src/services/userService.ts`
**Действие:** экранировать `%`/`_` в `search` перед `contains` (например, `search.replace(/[%_]/g, '\\$&')` + `escape`).
